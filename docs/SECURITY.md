# Data handling and deployment boundaries

- PBKDF2-SHA256 passwords with per-account random salts and 210,000 iterations; JWT issuer/audience/signature/expiry validation. Login and candidate registration have per-IP rate limits. Role authorization is server-enforced; candidate record access is restricted by ownership.
- Private FastAPI service requires a shared internal key; Compose exposes only the frontend on loopback. The browser never contacts Ollama or FastAPI. Production requires TLS termination, rotated secrets, backed-up encrypted storage and an organization-specific identity provider/policy review.
- Resumes have random storage filenames, bounded upload size (5 MiB), extension/signature checks, bounded DOCX archives, macro rejection, PDF encryption/page limits and text limits. Uploaded originals are served only as authorized attachments. A private named volume is owned by the API user. Parsers run separately as a non-root user. Scanned PDFs require a selectable-text replacement; OCR is intentionally unsupported. This is not an antivirus scanner; untrusted enterprise ingestion should add malware scanning and stronger parser isolation.
- Structured extraction is conservative: taxonomy names/aliases and explicit education, employment, project and technology headings. All extracted facts start Unverified. Human corrections retain original quotes and save before/after snapshots in review notes. Missed facts can be manually transcribed only from an exact stored quote. A quote establishes the resume's claim, not independently confirmed employment history.
- Semantic retrieval uses real local embeddings persisted in pgvector. Cosine similarity measures taxonomy text similarity only; candidates and employees are never scored. Semantic results require human confirmation.
- Inference input excludes resume text, identity and protected characteristics. DeepSeek produces schema-constrained JSON evidence selections. Exact membership and coverage checks reject fabricated, cross-skill, duplicate or omitted evidence. The application constructs explanatory prose from validated selections; there is no unchecked model prose. Proficiency is human-entered, never inferred. Missing means undocumented. Protected traits are never extracted into structured facts or used by the AI; original files and source previews may still contain user-provided personal data and are restricted.
- Extracted facts, AI results, human reviews and manual decisions are stored separately. Evidence and job requirement changes invalidate old analyses. Analysis versions, model name/digest, prompt/schema versions and hashes support reproducibility; raw prompts are not logged.
- Documents expire after 180 days. The worker removes original files, facts, dependent processing jobs, analyses and application review notes on expiry. Authorized users can erase documents or entire applications. Document erasure also removes application review notes so before/after correction snapshots cannot retain the deleted evidence. Application deletion cascades reviews, interviews and decisions; audit records retain IDs and action names without document contents. Account profile data has a separate lifecycle. Backups require separate retention/erasure policy; application-level deletion cannot erase historical backups.
- No outbound paid AI API is configured. Model pulls and dependency installation require network access; operation thereafter is local. Ollama images/model tags should be pinned by digest for deployment. Audit trail is application-level, not externally tamper-proof.
